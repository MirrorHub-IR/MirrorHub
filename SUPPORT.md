# Support

Use the repository documentation and issue forms to request help with MirrorHub.

## Before opening an issue

1. Check the README and the relevant guide in the docs directory.
2. Search existing issues and pull requests for the same problem.
3. Reproduce the behavior on the current default branch when possible.
4. Remove database credentials, API tokens, Cron keys, personal data, internal hostnames, and private logs from any report.

## Bug reports

Use the Bug report issue form. Include:

- MirrorHub commit or version/tag, if known.
- PHP version and enabled extensions.
- MySQL/MariaDB version.
- Web server and relevant rewrite configuration.
- Exact steps to reproduce and expected versus actual behavior.
- Sanitized error messages and the relevant server-side log excerpt.
- Whether the issue occurs on a fresh staging installation.

## Feature requests

Use the Feature request issue form. Explain the problem, the expected user workflow, alternatives considered, and any compatibility or migration implications.

## Security reports

Do not report exploitable vulnerabilities in public issues. Follow [SECURITY.md](SECURITY.md) and use GitHub private vulnerability reporting if it is enabled for this repository. If private reporting is unavailable, contact the maintainers privately before disclosing technical details.

## Scope

MirrorHub is an evolving open-source project maintained by volunteers. Support is best-effort; an issue submission does not imply a response-time commitment or a guaranteed fix.
