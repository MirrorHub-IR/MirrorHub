# میرورهاب (MirrorHub)

[![بررسی‌های خودکار](https://github.com/ahb1390/MirrorHub/actions/workflows/quality.yml/badge.svg?branch=main)](https://github.com/ahb1390/MirrorHub/actions/workflows/quality.yml)

[English](README.md)

MirrorHub یک برنامهٔ وب مبتنی بر PHP و MySQL/MariaDB برای جست‌وجوی میرورهای نرم‌افزاری، دسته‌بندی مخازن و ارائه‌دهندگان، دریافت پیشنهادهای جامعه و پایش وضعیت سرورهاست.

> **وضعیت پروژه:** در حال توسعه. بررسی‌های خودکار نحو و تست‌های دود موفق هستند، اما پیش از انتشار باید نصب واقعی، اتصال دیتابیس، مسیرهای HTTP، بازیابی بکاپ و API در محیط آزمایشی هم تست شوند.

## امکانات اصلی

- فهرست قابل جست‌وجوی میرورها با دسته‌بندی، پروتکل، فیلتر و صفحهٔ جزئیات مستقل.
- تفکیک وضعیت دسترس‌پذیری HTTP از بررسی تازگی metadata مخزن.
- تاریخچهٔ پایش، آپتایم روزانه، رخدادهای قطعی، داشبورد و اعلان‌های اختیاری.
- دریافت پیشنهاد میرور از کاربران؛ پیشنهادها پس از ثبت مستقیماً منتشر نمی‌شوند و باید مدیر آن‌ها را بررسی کند.
- API عمومی نسخهٔ ۱ با صفحه‌بندی، فیلترها، پاسخ JSON ساخت‌یافته و سند OpenAPI.
- راهنماهای مبتنی بر Markdown، CMS داخلی، اطلاعات SEO، نقشهٔ سایت و robots.txt.
- بکاپ و بازیابی پایگاه داده، حفاظت CSRF در جریان نصب و بخش‌های مدیریتی و بررسی‌های خودکار GitHub Actions.

## نیازمندی‌های فنی

- PHP 8.2 یا بالاتر؛ نسخهٔ 8.2 در CI آزمایش می‌شود.
- MySQL یا MariaDB و افزونهٔ PDO MySQL.
- Apache با پشتیبانی از URL rewriting و فایل .htaccess برای مسیرهای تمیز.
- افزونه‌های PHP پیشنهادی/موردنیاز در مسیرهای فعلی: pdo_mysql، mbstring، fileinfo و curl.
- در وضعیت فعلی برای ساخت فایل‌های CSS و JavaScript به Node یا نصب وابستگی Composer نیاز نیست.

## نصب سریع

راهنمای کامل در [docs/installation.fa.md](docs/installation.fa.md) است. مراحل کلی:

1. فایل‌های پروژه را روی هاست PHP قرار دهید.
2. دامنه را باز کنید؛ در نصب تازه، سایت به‌صورت خودکار به /setup.php منتقل می‌شود.
3. اطلاعات اتصال MySQL/MariaDB، آدرس کامل سایت (با زیرشاخه‌ای مانند /beta در صورت نیاز) و مشخصات حساب مدیر را وارد کنید.
4. Setup اتصال را آزمایش می‌کند، جداول برنامه را می‌سازد، تنظیمات محرمانه را ذخیره می‌کند و پس از تکمیل، مدیر را وارد پنل می‌کند. اگر مجوز فایل‌سیستم اجازه دهد، فایل setup.php نیز حذف می‌شود.
5. دستهٔ ارائه‌دهنده، میرورها و پروفایل سلامت metadata را تنظیم کنید.
6. برای پایش قابل‌اتکا، Cron واقعی سرور را طبق [راهنمای پایش](docs/monitoring.md) تنظیم کنید.

فایل تنظیمات محلی، رمز دیتابیس، توکن ربات، بکاپ و لاگ‌های تولیدی را داخل Git قرار ندهید.

## نمونهٔ استفاده از API

~~~sh
API_BASE="https://mirrorhub.ir/beta/api/v1"
curl --fail --silent --show-error "$API_BASE/mirrors?per_page=10"
curl --fail --silent --show-error "$API_BASE/categories?type=software"
curl --fail --silent --show-error "$API_BASE/status"
curl --fail --silent --show-error "$API_BASE/openapi.json"
~~~

مسیر ثبت پیشنهاد فقط یک درخواست در وضعیت انتظار بررسی ایجاد می‌کند و میرور را مستقیماً فعال نمی‌کند. برای پارامترها، قرارداد پاسخ، محدودیت‌ها و مثال‌ها به [مستندات API](docs/api-v1.md) مراجعه کنید. مسیرهای قدیمی api.php?action=... هم فعلاً برای سازگاری حفظ شده‌اند.

## نکتهٔ مهم دربارهٔ سلامت مخزن

پاسخ‌دادن سرور با HTTP به معنی به‌روز بودن همهٔ بسته‌ها یا تأیید صحت امضاهای GPG نیست. پروفایل‌های metadata فعلی تازگی/دسترس‌پذیری فایل مشخص‌شده را بررسی می‌کنند، اما امضای رمزنگاری‌شده و تمام hash بسته‌ها را به‌صورت کامل اعتبارسنجی نمی‌کنند. هنگام نصب نرم‌افزار، بررسی امضاهای عادی مدیر بستهٔ توزیع را غیرفعال نکنید.

## تست‌ها

GitHub Actions بررسی نحو همهٔ فایل‌های PHP، تست‌های دود امنیتی/رگرسیون و بررسی نحو JavaScript را اجرا می‌کند. این موارد جایگزین تست یکپارچه با MySQL/MariaDB واقعی یا تست مرورگر در محیط استقرار نیستند.
