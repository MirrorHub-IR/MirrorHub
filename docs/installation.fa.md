# راهنمای نصب و راه‌اندازی MirrorHub

MirrorHub دارای نصب‌کنندهٔ مرورگری است. در یک نصب تازه، بازکردن ریشهٔ سایت شما را به `/setup.php` هدایت می‌کند و نیازی به ساخت دستی `config.local.php` نیست.

## پیش‌نیازها

- PHP 8.2 یا جدیدتر.
- MySQL یا MariaDB و افزونهٔ `pdo_mysql`.
- افزونه‌های PHP موردنیاز برنامه: `mbstring`، `fileinfo` و `curl`.
- Apache با `mod_rewrite` و امکان استفاده از `.htaccess` برای مسیرهای تمیز.
- HTTPS برای استقرار عمومی.
- مجوز نوشتن محدود برای ساخت `config.local.php` در ریشهٔ برنامه و مجوز لازم برای ایجاد جدول‌ها و ایندکس‌ها در دیتابیس.

## نصب از مرورگر

1. فایل‌های پروژه را در ریشهٔ وب یا زیرشاخهٔ موردنظر قرار دهید.
2. آدرس اصلی سایت را باز کنید. در نصب تازه، انتقال موقت به `/setup.php` انجام می‌شود.
3. میزبان، پورت، نام دیتابیس، نام کاربری و رمز دیتابیس را وارد کنید.
4. دکمهٔ آزمایش اتصال دیتابیس را بزنید. این آزمایش داده ایجاد نمی‌کند؛ مرحلهٔ نصب در صورت نیاز ایجاد دیتابیس را نیز امتحان خواهد کرد.
5. آدرس کامل سایت و نام کاربری مدیر را وارد کنید. رمز مدیر باید حداقل ۱۲ نویسه باشد.
6. نصب را اجرا کنید. جداول اصلی، روابط، درخواست‌ها، آمار بازدید، ساختار پایش، CMS و وضعیت نصب آماده می‌شوند.
7. پس از موفقیت، نشست مدیر ساخته و مرورگر به `/admin/dashboard.php` منتقل می‌شود.

## ساخت دیتابیس و مجوزهای هاست

نصب‌کننده ابتدا تلاش می‌کند به دیتابیس هدف متصل شود. اگر دیتابیس هنوز وجود نداشته باشد، تلاش می‌کند آن را با کاربر واردشده بسازد. کاربر دیتابیس باید مجوز `CREATE DATABASE` برای این حالت یا مجوزهای لازم برای استفاده از دیتابیسی را داشته باشد که از پنل هاست ایجاد کرده‌اید.

در هاست اشتراکی، معمولاً باید دیتابیس و کاربر آن را از پنل هاست بسازید و سپس همان اطلاعات را در Setup وارد کنید. برای نصب، رمز کاربر `root` را وارد نکنید. اگر اتصال سرور برقرار شود اما ایجاد دیتابیس مجاز نباشد، پیام راهنما دریافت می‌کنید.

Setup تنها دیتابیس خالی یا دیتابیسی را ادامه می‌دهد که جدول وضعیت نصب MirrorHub آن نشان دهد نصب قبلی هنوز در حال تکمیل است. دیتابیس دارای جدول‌های نامرتبط یا نصب کامل‌شده دوباره مقداردهی اولیه نمی‌شود. اگر نصب در میانهٔ کار متوقف شود، وضعیت نصب برای تلاش مجدد حفظ می‌شود.

## تنظیمات و قفل نصب

پس از اعتبارسنجی اتصال، اطلاعات اتصال در فایل خصوصی `config.local.php` با مجوز محدود نوشته می‌شود. فایل تنظیمات واقعی را در Git قرار ندهید. متغیرهای محیطی `MIRRORHUB_DB_*` و `MIRRORHUB_SITE_URL` بر مقادیر فایل محلی اولویت دارند؛ اگر از متغیر محیطی استفاده می‌کنید، مقادیر فرم باید با آن‌ها هماهنگ باشد.

پس از تکمیل جدول‌های برنامه و ساخت حساب مدیر، وضعیت نصب در دیتابیس ثبت و فایل قفل `.mirrorhub-installed` در صورت امکان ایجاد می‌شود. Setup تلاش می‌کند فایل اجرایی `setup.php` را هم حذف کند. اگر میزبان اجازهٔ حذف فایل را ندهد، قفل دیتابیس همچنان از نصب دوباره جلوگیری می‌کند؛ در این حالت فایل Setup را از روی هاست حذف کنید. فایل `.mirrorhub-installed` و `config.local.php` نباید از وب قابل دریافت باشند.

نصب‌کنندهٔ موجود در مخزن برای راه‌اندازی نسخه‌های تازه نگه‌داری می‌شود؛ بنابراین حذف خودکار فایل روی هاست به معنی حذف آن از مخزن Git نیست.

## URL و نصب در زیرشاخه

اگر برنامه زیر آدرس `https://example.com/beta` نصب شده، مقدار آدرس سایت را دقیقاً به همین شکل وارد کنید. Setup از مقدار ذخیره‌شده برای انتقال به داشبورد استفاده می‌کند. در نصب‌های عمومی از HTTPS استفاده کنید.

## پس از نصب

- صفحهٔ اصلی، جست‌وجو، جزئیات میرور و `/status.php` را بررسی کنید.
- `/api/v1/openapi.json` و مسیرهای API نسخهٔ ۱ را آزمایش کنید.
- دسته‌های ارائه‌دهنده و میرورها را تنظیم کنید.
- برای اجرای قابل‌اتکای پایش، Cron واقعی سرور را مطابق [راهنمای پایش](monitoring.md) تنظیم کنید.
- یک نسخهٔ پشتیبان تهیه و فرایند بازیابی آن را در محیط آزمایشی بررسی کنید.

## عیب‌یابی

- **خطای اتصال:** میزبان، پورت، نام کاربری، رمز، مجوز دسترسی به دیتابیس و محدودیت اتصال از هاست را بررسی کنید.
- **ساخت دیتابیس مجاز نیست:** دیتابیس را از پنل هاست ایجاد کنید و نام آن را در Setup وارد کنید.
- **خطای ذخیرهٔ تنظیمات:** مجوز نوشتن محدود برای فایل و پوشهٔ ریشه را فراهم کنید؛ از دادن مجوز نوشتن عمومی به کل پروژه خودداری کنید.
- **خطای ایجاد جدول یا Migration:** مجوز ساخت جدول، ایندکس و کلید خارجی را بررسی کنید. جزئیات داخلی در لاگ سرور ثبت می‌شوند و رمز دیتابیس در خروجی عمومی نشان داده نمی‌شود.
- **خطای 404 در مسیرهای تمیز:** `mod_rewrite` و اجازهٔ استفاده از `.htaccess` را بررسی کنید. در Nginx باید قوانین معادل به‌صورت جداگانه تنظیم شوند.
- **خطای 503 بعد از نصب:** اگر دیتابیس موقتاً در دسترس نیست، Setup را دوباره اجرا نکنید؛ اتصال و مجوزهای دیتابیس نصب فعلی را بررسی کنید.
