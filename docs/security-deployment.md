# امنیت پایه و راه‌اندازی امن MirrorHub

## تنظیمات محرمانه

اعتبارنامه‌های دیتابیس و توکن‌های عملیاتی را در سورس عمومی ثبت نکنید. در هاست یکی از روش‌های زیر را انتخاب کنید:

- متغیرهای محیطی: `MIRRORHUB_DB_HOST`، `MIRRORHUB_DB_NAME`، `MIRRORHUB_DB_USER`، `MIRRORHUB_DB_PASS` و در صورت نیاز `MIRRORHUB_SITE_URL`، `MIRRORHUB_ENVIRONMENT` و `MIRRORHUB_MONITOR_CRON_KEY`.
- فایل محلی: `config.local.example.php` را به `config.local.php` کپی کنید، مقادیر نمونه را با تنظیمات واقعی جایگزین کنید و فایل را خارج از Git نگه دارید. فایل محلی در `.gitignore` قرار گرفته و دسترسی مستقیم آن در Apache مسدود شده است.

اگر اعتبارنامه‌ای قبلاً در یک مخزن عمومی ثبت شده است، آن را افشاشده فرض کنید و از سمت میزبان تغییر دهید. تغییر فایل در آخرین commit تاریخچهٔ Git را پاک نمی‌کند؛ پاک‌سازی تاریخچه باید پس از تعویض اعتبارنامه‌ها و با هماهنگی همکاران انجام شود.

## نصب اولیه

فایل `install.php` دیگر حساب مدیر با رمز پیش‌فرض ایجاد نمی‌کند. نصب باید با ارسال فرم دارای CSRF انجام شود و نام کاربری و رمز عبور مدیر را خودتان تعیین کنید. رمز باید حداقل ۱۲ نویسه داشته باشد. پس از نصب موفق، فایل `install.php` را از مسیر عمومی حذف کنید یا دسترسی مستقیم به آن را در سرور مسدود کنید.

نام دیتابیس فقط می‌تواند شامل حروف انگلیسی، رقم و زیرخط باشد. در محیط تولید، خطاهای اتصال به دیتابیس به بازدیدکننده جزئیات داخلی را نشان نمی‌دهند.

## بکاپ و بازیابی

نسخهٔ ۲ بکاپ، جدول‌های لینک چندگانهٔ درخواست‌ها، تاریخچه و وضعیت پایش و تنظیمات پایش را نیز ثبت می‌کند. فایل JSON شامل تنظیمات خصوصی اعلان است؛ آن را مثل یک فایل محرمانه نگهداری کنید.

- پیش از بازیابی «جایگزینی کامل»، از وضعیت فعلی یک بکاپ بگیرید.
- بکاپ نسخهٔ ۱ که تاریخچهٔ پایش و لینک‌های چندگانه را ندارد، در حالت «جایگزینی کامل» پذیرفته نمی‌شود تا داده‌های فعلی ناخواسته حذف نشوند. حالت «حفظ اطلاعات فعلی» برای واردکردن داده‌های قدیمی در دسترس است.
- برای اثبات سلامت بکاپ، آن را در یک محیط آزمایشی جداگانه بازیابی و شمار رکوردها را بررسی کنید؛ دانلود موفق به‌تنهایی سلامت بازیابی را ثابت نمی‌کند.

## تست‌های خودکار

گردش‌کار GitHub Actions نحو فایل‌های PHP و JavaScript را بررسی می‌کند و تست‌های smoke مربوط به پیکربندی، نصب، CMS و پوشش جدول‌های بکاپ را اجرا می‌کند. این آزمون‌ها جایگزین تست یکپارچه با دیتابیس آزمایشی یا تست دستی بازیابی نیستند.
